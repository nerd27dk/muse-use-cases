## Repeatable manual cycle

Full instructions with error handling: `RUNBOOK.md`. Short form: capture one GET, store raw privately, fingerprint into `snapshots/`, diff against the previous fingerprint, triage (added = new to us; removed = noted, never auto-deleted; changed = read the private raws), decisions recorded separately and privately. Commits, pushes and any RAISE publication are GO-gated.

## Method and limits

- The differ is read-only, no network; compares the union of all fields (future fields surface); key order ignored; arrays ordered except `origins` (set semantics); absent key vs null distinguished; duplicates/malformed input are errors. Exit 0/1/2 = no diff / diff / bad input.
- Fingerprints detect change exactly but show no content; IDs and the fact of change stay visible - not anonymous. They discover nothing by themselves: a stalled source yields a clean diff, not new stories.
- Raw payloads stay private: license scope over third-party post texts is unverified (MIT covers the software; the crowd feed has no license metadata).
- Dates: `addedAt` exists only for submissions; `refreshedAt` stamps the whole merge. Proposed, not implemented: firstSeenAt per ID = when WE first saw it (here: capture time), not a creation or upstream-addition date.
- API rate limits/availability unverified: one GET per cycle is observed to work, not promised.
